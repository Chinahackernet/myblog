# 生产故障应急响应

## 事件分级

按用户影响、数据风险、扩散速度和合规影响分级。P1 事件立即建立指挥频道和时间线，指定指挥官、执行者、记录员、沟通负责人；未经授权不要并行执行修复。

## 止血与取证

优先恢复最小可用服务：限流、摘除异常节点、切换只读、阻断恶意流量或回滚已知安全版本。止血前后保存配置、进程、连接、日志、指标和最近变更，避免清理现场导致无法复盘。

```bash
date -Is; uptime; ss -s; ps auxww; journalctl -b -n 200
```

区分入口不可达、无健康实例、依赖超时、资源耗尽、数据错误和安全事件。每次动作写明假设、风险、预计结果和撤销命令；结果不符就回到证据。

恢复后执行合成交易、数据完整性和权限验证，观察一个业务周期再宣布结束。复盘形成负责人、截止时间和可验证结果；日志、快照和命令记录使用统一时间、只读副本和访问审计。

## 事件记录模板

```text
开始时间/发现渠道：
影响服务、租户、区域：
当前 SLO 消耗与数据风险：
已证实事实 / 未证实假设：
止血动作、执行人、结果：
下一检查点与升级条件：
恢复验证与回切条件：
```

取证顺序优先保存易失数据（进程、连接、路由、内存指标），再保存配置、日志和磁盘快照。涉及安全事件时隔离受影响凭据和主机，保留时间线与 hash；不要把原始个人数据复制到公共工单。
