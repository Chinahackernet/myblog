# MogileFS 与 FastDFS：分布式文件存储的角色、故障域与扩容

## 1. 角色与一致性边界

MogileFS 由 Tracker、MogStored 和元数据数据库组成，Tracker 负责定位与副本策略，MogStored 保存对象；FastDFS 通常由 Tracker、Storage Group 和 Storage 节点构成。两者更适合大文件/对象分发，不应直接当作强一致数据库或 POSIX 文件系统。

设计时先定义对象命名、大小上限、校验和、复制因子、读写路径、删除语义和生命周期。元数据数据库、Tracker quorum、Storage 节点和 Nginx 代理必须分布在独立故障域。

## 2. 写入、读取与故障模型

写入路径应先落对象再提交元数据，或使用系统明确规定的顺序；任何中间失败都需要可重试、幂等和孤儿对象清理。读取通过 Tracker/命名服务定位副本，代理层应设置连接超时、读取超时、重试次数和请求 ID。

```text
client -> Nginx -> Tracker -> Storage-A/B
                         |-> metadata DB
```

常见故障包括 Tracker 不可达、元数据库延迟、单组副本不足、磁盘坏块、对象校验失败和代理缓存脏数据。排障先核对对象 ID、路由、节点状态和校验和，再执行隔离/重平衡；不要直接删除“看起来重复”的文件。

## 3. 故障域与副本策略

副本应跨主机、机架和可用区分布，副本数由对象重要性、成本和 RPO 决定。健康检查至少包括磁盘水位、inode、SMART、读写延迟、对象抽样校验、复制积压和元数据错误。Storage 节点达到阈值应先停止接收新写，再迁移对象，不要等磁盘 100% 才处理。

```bash
df -hT; df -ih
smartctl -a /dev/sdb
iostat -xz 1 5
find /srv/storage -type f -size +1G -print0 | xargs -0 sha256sum > /tmp/sample.sha256
```

## 4. 扩容、迁移与 Nginx 代理

扩容顺序是新增节点→加入 Tracker/Group→小比例写入→观察副本与错误→渐进式重平衡→更新代理权重。迁移必须限制带宽和并发，防止占满业务链路；完成后随机抽样校验对象内容与元数据。

Nginx 代理配置要限制上传大小、临时目录、超时、Range 请求和缓存键，并保留上游状态码与对象 ID。对下载可使用 `sendfile`/异步 I/O，但要结合文件系统、TLS 和内核页缓存压测。

## 验收与恢复

验收包括单 Storage 故障、整组故障、Tracker 少数派、数据库只读、代理证书过期和磁盘水位告警。恢复后核对副本数量、对象校验和、孤儿对象、元数据计数及业务下载成功率；RPO/RTO 必须用真实对象集演练而不是只启动服务。

## 5. 一致性巡检与生命周期

对象巡检采用分层采样：先查元数据中存在但节点缺失的对象，再查节点存在但元数据无记录的孤儿对象，最后对高价值对象做内容校验。修复任务要限速、可暂停、可重试并记录对象 ID；任何删除操作先进入隔离区，经过业务确认后再清理。生命周期规则按热数据、归档、删除和合规保留分开定义，不能用定时 `find -delete` 代替策略引擎。

扩容验收除吞吐外还要看副本重平衡对线上延迟的影响、故障域分布、恢复后的读写比例和代理缓存命中。只有在对象校验、元数据计数和业务下载都通过后，才允许关闭旧节点。

## 6. 运维接口与安全

Tracker、Storage 和元数据数据库的管理接口只允许管理网访问，服务账号按角色拆分，禁止在代理日志中记录完整签名 URL。上传下载使用短期授权和大小/类型白名单；对象名称、元数据和校验结果写入审计流，审计流本身跨故障域保存。节点退役先禁止新写、完成迁移、做全量抽样校验，再吊销凭证和清理磁盘。

生产容量评审还要核对单对象并发、目录/索引热点、代理缓存容量、跨区带宽和恢复期临时空间；这些限制应在监控中形成可行动的阈值，而不是只写在设计文档里。

高价值对象可采用双人复核的删除流程和不可变归档副本；普通缓存对象则允许按 TTL 淘汰。把对象分类写入元数据后，复制、备份、加密和保留策略才能自动化执行。
