# Linux 日志与故障定位

## 1. 先建立时间线

记录故障开始时间、影响范围、最后一次正常时间、相关发布和变更。日志查询必须带时间范围。

## 2. systemd 日志

```bash
journalctl -b --no-pager
journalctl -u nginx --since '30 min ago' --no-pager
journalctl -p err --since 'today' --no-pager
journalctl -k --since '1 hour ago' --no-pager
```

## 3. 文件日志

```bash
tail -n 200 /var/log/messages 2>/dev/null
tail -n 200 /var/log/syslog 2>/dev/null
grep -Ei 'error|fail|timeout|拒绝|异常' /var/log/*.log 2>/dev/null | tail -100
```

不要用无时间范围的全盘 `grep` 代替分析；大日志会造成额外 IO。

## 4. 关联进程与连接

```bash
ps -ef | grep -v grep | grep <服务名>
lsof -p <PID> | head -50
ss -ntp | grep <端口>
```

把日志中的时间、请求 ID、PID、客户端地址与监控指标关联起来。单条错误日志通常只能说明现象，不能直接证明根因。

## 5. 故障处理记录

```text
现象：
影响：
时间线：
证据（日志/指标/命令输出）：
临时缓解：
根因：
永久修复：
预防措施：
```
