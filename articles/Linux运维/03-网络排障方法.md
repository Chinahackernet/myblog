# Linux 网络排障方法

## 排障顺序

按“链路—地址—路由—解析—端口—应用”逐层确认，不要一开始就重启网络服务。

## 1. 链路、地址与路由

```bash
ip -br link
ip -br addr
ip route
ip route get 8.8.8.8
```

检查网卡是否 UP、地址是否正确、默认路由是否存在。云主机还要核对安全组和子网 ACL。

## 2. DNS 与连通性

```bash
ping -c 4 <网关地址>
getent hosts example.com
resolvectl status 2>/dev/null || cat /etc/resolv.conf
```

区分“域名解析失败”和“解析成功但端口不通”。生产环境不应仅凭 ping 判断业务可用性。

## 3. 端口与路径

```bash
ss -lntup
nc -vz <目标地址> <端口>
tracepath <目标地址> 2>/dev/null || traceroute <目标地址>
curl -I --connect-timeout 5 http://<目标地址>:<端口>/
```

监听端口存在不代表应用健康；还要检查进程、反向代理、负载均衡和上游依赖。

## 4. 抓包原则

```bash
sudo tcpdump -ni any host <目标地址> and port <端口>
```

只在明确过滤条件和时间范围后抓包。抓包文件可能包含敏感数据，应限制权限并及时清理。

## 常见判断

- 无 ARP/邻居响应：优先检查二层、网卡、VLAN 或云网络。
- 有 SYN 无 SYN-ACK：检查服务监听、防火墙和返回路由。
- TCP 已建立但请求超时：检查应用线程、上游依赖和连接池。
- 只有域名失败：检查 DNS、搜索域和解析记录。
