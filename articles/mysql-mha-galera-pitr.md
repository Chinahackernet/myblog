# MySQL MHA/Galera、半同步与时间点恢复

## 1. 方案取舍

MHA/Orchestrator 类方案面向异步或半同步复制的主从提升，写入仍以单主为主；Galera 提供多主同步复制，但对网络 RTT、冲突、流控和大事务更敏感。不要把“多节点”直接等同于“无损高可用”。

## 2. 故障切换门槛

自动切换前必须确认旧主已 fencing 或禁止写入，候选副本具备最新 GTID、只读策略、业务账号和 binlog 保留。切换后更新代理、连接池和 DNS，并验证写入、读一致性和回切。

## 3. Galera 关键指标

关注 `wsrep_cluster_size`、`wsrep_local_state_comment`、`wsrep_flow_control_paused`、冲突和 IST/SST。节点加入前校验 SST 认证、磁盘空间和 donor 负载；滚动升级一次只动一个节点，并保持 quorum。

## 4. 时间点恢复（PITR）

流程为：全量备份 → 保留连续 binlog → 恢复到临时实例 → 应用 binlog 至目标时间 → 校验业务不变量 → 切换连接。备份必须加密、跨故障域复制并定期恢复演练。

```bash
mysqlbinlog --start-datetime='2026-09-04 10:00:00' --stop-datetime='2026-09-04 10:17:00' binlog.000123 | mysql -u restore -p
```

## 5. 风险与回滚

大事务、DDL、时钟偏差和 binlog 清理都可能破坏恢复窗口。恢复期间不覆盖原库；保留原始备份、binlog 和审计日志。切换失败时将流量切回旧主前，必须确认新主没有接受未复制写入。

## 切换 Runbook

1. 宣布冻结窗口并停止高风险 DDL；2. 验证旧主 fencing、复制位点和候选节点健康；3. 提升候选节点并设置只读/写入策略；4. 更新 HAProxy/ProxySQL/连接池；5. 执行合成写入、读一致性和关键业务校验；6. 解除写入冻结并观察复制与锁指标。

MHA/Galera 的自动化必须有“不能切换”的条件：多数派不足、候选节点落后超过 RPO、旧主无法 fencing、磁盘空间不足或 schema 不兼容。宁可保持只读，也不要在双主状态下恢复写入。

PITR 校验除文档数外还包括外键/唯一约束、账务合计、队列去重、最后提交时间和关键用户抽样。恢复脚本应支持 dry-run、断点和校验清单，失败时不会破坏原始备份。
