# SLO/SLI、容量规划、应急响应、灾难恢复与合规

## 1. SLI/SLO 与错误预算

SLI 是可测量的可靠性指标，如成功率、延迟、可用性和新鲜度；SLO 是时间窗口内的目标；错误预算是允许的失败量。SLO 必须对应用户旅程，不能只用 CPU/内存代替。

```text
可用性 SLI = 成功请求数 / 合法请求总数
错误预算 = 1 - SLO
```

发布门禁、告警优先级和团队工作量应消费同一错误预算；预算耗尽时暂停高风险发布，优先修复可靠性。

## 2. 容量与成本

用峰值、增长率、冗余和故障余量建模 CPU、内存、连接、IOPS、带宽、日志和对象存储。每月检查预测误差，容量阈值提前于硬上限触发；扩容计划同时包含配额、许可证、机柜/区域和恢复时间。

## 3. 事件响应

事件分级、指挥官、沟通负责人和记录员角色预先定义。处置顺序是止血（限流/隔离）→ 保证证据 → 恢复最小服务 → 验证数据 → 回切和复盘。复盘关注系统性原因，不以追责替代改进。

## 4. 灾难恢复与合规

把依赖、RPO/RTO、恢复顺序、联系人和授权写成 runbook；备份加密、异地、不可变并定期恢复。合规要求最小权限、审计留存、密钥轮换、补丁 SLA、漏洞豁免到期和个人数据脱敏。演练结果必须形成差距清单和整改期限。

## 告警与值班

告警只针对可行动的 SLO 消耗、数据损坏风险或容量临界点；把症状告警和原因告警分层，设置抑制和维护窗口。值班手册包含联系人、权限、止血命令、证据采集、升级条件和恢复验证，不把个人记忆当作流程。

容量预测至少采用趋势、季节性和故障余量三种情景，并定期回测误差。关键资源按“正常峰值 + 单故障余量 + 发布峰值”规划；日志和备份容量还要考虑保留期、压缩率、加密开销和恢复并发。

灾备演练以业务事务验证为终点：模拟区域不可用、凭据失效、DNS 误配、备份损坏和依赖降级，记录实际 RTO/RPO 与目标差距。合规控制要能给出证据链：谁在何时以何权限做了什么、产生什么结果、何时撤销。
