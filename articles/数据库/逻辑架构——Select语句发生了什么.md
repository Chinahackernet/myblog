## 连接器

如果要操作数据库，第一步肯定是要连接它，就像你要进入公司，肯定是要先进门一样。

​  

当客户端发起连接后，`连接器`就是接受并处理请求的地方，它主要包括：

-   建立连接
-   权限认证
-   连接管理

​  

在Linux系统中，一般使用以下命令来建立连接。

```shell
mysql -h$ip -u$user -P$port -p	
```

其中：

-   $ip：表示MySQL的IP地址
-   $user：表示用户名
-   $port：表示MySQL的端口

  

另外，`-p`表示MySQL的密码，可以直接跟在其后面，如`mysql -h$ip -u$user -P$port -p'123456'`，如果不写，则需要手动输入。

​  

当在客户端敲入以上命令之后，客户端就会向服务端发起连接请求，首先进行TCP的三次握手，因为MySQL是基于TCP协议进行传输的。

![image.png](assets/数据库/逻辑架构——Select语句发生了什么/逻辑架构——Select语句发生了什么-3.png)

  

然后就需要输入密码进行验证，如果验证不通过，则会报 `Access denied`的错误。

![image.png](assets/数据库/逻辑架构——Select语句发生了什么/逻辑架构——Select语句发生了什么-4.png)

  

如果用户密码都没有问题，连接器就会获取该用户的权限，然后保存起来，后续该用户在此连接里的任何操作，都会基于连接开始时读到的权限进行权限逻辑的判断。

![image.png](assets/数据库/逻辑架构——Select语句发生了什么/逻辑架构——Select语句发生了什么-5.png)

  

连接完成后，如果没有后续的操作，这个连接就处于空闲状态，我们可以通过`show processlist`命令查看。

![image.png](assets/数据库/逻辑架构——Select语句发生了什么/逻辑架构——Select语句发生了什么-6.png)

  

那这个空闲连接会一直存在嘛？

  

如果一个连接一直没有动作，它就会持续占用连接，如果连接数满了，其他连接也就进不来，这有点占着茅坑不拉屎的感觉。为了解决这个问题，MySQL定义了空闲连接的最大空闲时间，默认是8小时（28000秒）。如果超过了该时间，连接器会主动断开该连接，可以通过`show variables like 'wait_timeout';`命令查看。

![image.png](assets/数据库/逻辑架构——Select语句发生了什么/逻辑架构——Select语句发生了什么-7.png)

  

如果连接断开过后，客户端再次进行操作的话，就会收到`Lost connection to MySQL server during query`的错误，如果想继续使用，就需要重新建立连接了。

​  

我们上面说如果连接持续占用，当连接数满了，其他连接就进不来了，那怎么知道MySQL现在的连接数限制是多少呢？

​  

可以通过`show variables like 'max_connections';`命令查看。

![image.png](assets/数据库/逻辑架构——Select语句发生了什么/逻辑架构——Select语句发生了什么-8.png)

  

我这里现实的最大连接数是3000（默认是151），如果连接数超过这个值，就会收到`Too many connections`报错，这时候如果想要连接应该怎么办呢？

​  

连接主要分为短链接和长连接，所谓短链接就是使用的时候建立连接，用完就释放连接。而长连接则是建立连接后会一直占用连接，直到主动断开或者被动断开。

​  

在实际使用中，使用长连接的好处是可以减少建立连接以及释放连接的过程，所以一般推荐使用长连接。

​  

但是，全部使用长连接过后，你会发现MySQL的内存涨的特别快，这是因为 MySQL 在执行查询过程中临时使用内存管理连接对象，这些连接对象资源只有在连接断开时才会释放。如果长连接累计很多，将导致 MySQL 服务占用内存太大，有可能会被系统强制杀掉（OOM），这样会发生 MySQL 服务异常重启的现象。

​  

那应该怎么解决呢？

​  

MySQL主要提供两种解决办法：

1.  定期断开连接。
2.  重新初始化连接。在`MySQL5.7`以后的版本中，提供`mysql_reset_connection`来重新初始化连接，这个过程不会重连或者重新做权限验证，但是会将连接恢复到刚创建完时的状态。

​  

到这，连接器的主要功能介绍完了，其主要功能如下：

1.  与客户端建立连接
2.  做权限验证
3.  维护管理连接

## 查询缓存

顾名思义，`查询缓存`就是查询的时候使用的缓存。`查询缓存`是以`key-value`的形式保存在内存中，`key`是查询语句，`value`是查询结果。

​  

当MySQL接收到一个select请求过后，会先在`查询缓存`里查看之前是否有执行过这个语句，如果有直接返回缓存里的值，如果没有再进行下一步操作，待结果出来后，再保存到查询缓存中。

​  

可以看到，如果命中查询缓存，MySQL不需要再执行后面复杂的操作，直接返回结果，效率很高。

​  

但是，在实际使用中，大多数情况下都不建议使用`查询缓存`，为什么呢？

​  

因为查询缓存失效非常的频繁。只要对一张表进行更新操作，这个表上的所有缓存都会清空，你前一面费劲巴拉的把数据缓存起来，还没开始用，下一秒就清空了，所有的力气都白费了。对于常更新的表来说，查询缓存的命中率非常低，它适合一些静态表，半年不更新一次的那种。

​  

你可以通过`show variables like 'query_cache_type';`命令来查看查询缓存是否开启。

![image.png](assets/数据库/逻辑架构——Select语句发生了什么/逻辑架构——Select语句发生了什么-9.png)

  

> Tips：在MySQL8.0以后的版本，直接将查询缓存整块功能删除了。需要注意的是移除的是server层的查询缓存。

## 分析器

如果一个查询语句在查询缓存中没有命中，就会着手去执行这个语句得到结果。

​  

首先就会到分析器，它主要做词法分析和语法分析。

1.  词法分析。MySQL 会根据你输入的字符串识别出关键字出来，构建出 SQL 语法树，这样方便后面模块获取 SQL 类型、表名、字段名、 where 条件等等。
2.  语法分析。根据词法分析的结果，语法解析器会根据语法规则，判断你输入的这个 SQL 语句是否满足 MySQL 语法。

经过了分析器，MySQL已经知道要做什么了，但是在做之前还需要经过一系列优化。

​  

优化器的主要工作就是确定SQL语句的执行方案，比如表里有多个索引，优化器会基于成本考虑，择优选择使用哪个索引。

## 执行器

在执行的时候，会先判断是否有执行权限，如果没有 就会返回没有权限的错误。

​  

如果有权限，就会根据不同的引擎调用不同的接口进行执行操作。

​  

以下面的例子进行说明：

```sql
select * from user where name='joker';
```

  

首先，假如name没有索引

1.  查询user表的第一行，判断name值是否为joker，如果不是则跳过，如果是则将这行保存到结果集。
2.  继续查询下一行，重复相同的判断逻辑，直至最后一行
3.  执行器将上述满足条件的结果集返回给客户端

​  

其次，假如name上有索引

1.  首先根据name是值在name索引数中找到叶节点
2.  然后回表根据主键值在聚簇索引中找到叶节点的数据页
3.  然后把数据保存到结果集
4.  重复操作获取满足条件的下一行
5.  执行器将上述满足条件的结果集返回给客户端

​  

## 总结

MySQL是典型的CS架构，Sever端主要包含以下逻辑模块：

-   连接器：建立连接，管理连接、校验用户身份；
-   查询缓存：查询语句如果命中查询缓存则直接返回，否则继续往下执行。MySQL 8.0 已删除该模块；
-   解析器：通过解析器对 SQL 查询语句进行词法分析、语法分析，然后构建语法树，方便后续模块读取表名、字段、语句类型；
-   优化器：基于查询成本的考虑， 选择查询成本最小的执行计划；
-   执行器：根据执行计划执行 SQL 查询语句，从存储引擎读取记录，返回给客户端；
