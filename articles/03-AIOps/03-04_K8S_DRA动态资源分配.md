# DRA 介绍
## 什么是 DRA
DRA 是 Kubernetes 中用于管理"专用硬件资源"(GPU、FPGA、高性能网卡/NIC、TPU 等)的一套原生 API 框架。它把设备当作一等公民,通过声明式的方式让 Pod 描述"我需要什么样的设备",再由调度器去匹配集群中实际可用的硬件,而不是简单地要求"给我 N 个某类资源"。

核心 API 对象(位于 `resource.k8s.io` API group)，如果把 DRA（Dynamic Resource Allocation） 和存储（CSI） 对比来看，就会非常容易理解。

| 存储（CSI） | DRA（设备） | 作用 |
| --- | --- | --- |
| StorageClass (SC) | DeviceClass | 定义"申请哪种资源" |
| PersistentVolume (PV) | ResourceSlice | 集群有哪些资源可以提供 |
| PersistentVolumeClaim (PVC) | ResourceClaim | 用户申请资源 |
| PVC 模板（StatefulSet volumeClaimTemplates） | ResourceClaimTemplate | Pod 自动创建 ResourceClaim |


这个设计思路类似于 Kubernetes 处理持久卷(Persistent Volume)的方式——申领(Claim)和实际资源(设备)分离,由调度器做撮合。

## 为什么需要 DRA
在 DRA 之前，Kubernetes 使用的是 Device Plugin(设备插件)+ Extended Resources 机制,例如 `nvidia.com/gpu: 2`。这种方式有明显局限:

1. 只能按整数计数,无法按属性精细匹配DRA 允许工作负载按属性(而非整数数量)请求专用硬件,把设备调度从"给我一块 GPU"变成"给我一块满足这些条件的设备",比如 GPU 显存大小、产品型号、拓扑结构或驱动能力。
2. 设备初始化与 Pod 生命周期强耦合DRA 的引入是为了解决设备需求更复杂的场景,比如把设备的初始化与分配从 Pod 生命周期中解耦出来,以及支持容器和 Pod 之间动态共享设备。 
3. 无法表达"分数化"/共享/拓扑感知等高级需求:比如多个 Pod 共享同一块 GPU 的不同切片、要求设备处于同一 NUMA 节点等,Device Plugin 模型很难优雅表达。
4. 调度器缺乏全局视角DRA 让调度器获得设备属性和集群拓扑的全局视图,从而形成更"流动"的资源池——调度器可以根据实际硬件可用情况而非静态标签来优化放置,这在 GPU/AI 场景下尤其重要。

DevicePlugin：用户申请 1 个 GPU → 调度器随机选节点 → Kubelet 本地分配 -> Pod 启动后显存不够 OOM

DRA：用户显式申请一个"显存>40Gi 的 GPU" → 调度器精确匹配 → 预分配成功 → Pod 正常启动

## DRA版本演进历史
v1.26：以 alpha 特性首次引入

v1.32：主体 DRA 特性进入 beta 阶段

v1.34：DRA 核心正式 GA，resource.k8s.io API group 中多个 API 毕业为稳定版，但`DRAConsumableCapacity` 特性门控需要手动开启。开启方法如下：

```bash
修改控制节点manifest，新增特性门控参数
# vim /etc/kubernetes/manifests/kube-apiserver.yaml
---feature-gates=DRAConsumableCapacity=true
# vim /etc/kubernetes/manifests/kube-scheduler.yaml（调度器要按可消费容量做分配）
---feature-gates=DRAConsumableCapacity=true
# vim /etc/kubernetes/manifests/kube-controller-manager.yaml（ResourceClaim controller 负责把 Template 实例化成 Claim）
---feature-gates=DRAConsumableCapacity=true

修改静态 Pod manifest 后，kubelet 会自动重建这三个组件（等 kubectl get pod -n kube-system 里 apiserver/scheduler/controller-manager 重启完成）。
# vim /var/lib/kubelet/config.yaml，加：
featureGates:
  DRAConsumableCapacity:true
然后重启：
# systemctl restart kubelet
```

v1.36： 默认开启`DRAConsumableCapacity` 特性门控，建议 1.36+版本的 k8s 使用 DRA。

# <font style="color:rgb(0, 0, 0);">GPU Operator 安装并启用 DRA</font>
目前官方推荐做法是:GPU Operator 负责装驱动/容器运行时等基础设施，DRA Driver 作为独立 Helm chart 与 GPU Operator 配合安装(NVIDIA 未来计划把 DRA Driver 直接集成进 GPU Operator，目前仍需分开装)。

## **<font style="color:rgb(0, 0, 0);">GPU Operator 安装</font>**
安装 GPU Operator 时需要指定不安装 DevicePlugin，否则会和后续安装的 DRA GPU Plugin 冲突。

```bash
helm repo add nvidia https://helm.ngc.nvidia.com/nvidia 
helm repo update

helm upgrade --install --wait gpu-operator \
     -n gpu-operator --create-namespace \
     nvidia/gpu-operator \
     --set driver.version="580.126.20" \
     --set driver.enabled=true \
     --set devicePlugin.enabled=false 
```

## **<font style="color:rgb(0, 0, 0);">DRA 安装</font>**
NVIDIA 提供的 DRA Driver：`dra-driver-nvidia-gpu` ，包含了下面两个 plugin：

+ GPU Plugin：用于替代之前的 DevicePlugin，即：https://github.com/nvidia/k8s-device-plugin
+ ComputeDomain Plugin：此插件专门用于支持Multi-Node NVLink (MNNVL)，这是 NVIDIA GB200 NVL72 等新一代系统实现节点间 GPU 高速直连的关键技术。它引入 ComputeDomain 这一抽象概念，用于在多个 Pod（可能跨节点）之间自动建立并保障一个安全、隔离的 NVLink 通信域。大部分主流的 GPU 都是用不上这个功能的，默认关闭即可。

安装命令如下：

```bash
helm upgrade --install nvidia-dra-driver-gpu nvidia/nvidia-dra-driver-gpu \
    --create-namespace \
    --namespace nvidia-dra-driver-gpu \
    --set resources.gpus.enabled=true \
    --set resources.computeDomains.enabled=false \
    --set gpuResourcesEnabledOverride=true \
    --set nvidiaDriverRoot=/run/nvidia/driver
```

## 使用
### <font style="color:rgb(0, 0, 0);">运行DRA GPU Pod</font>
创建 ResourceClaimTemplate 申请一个 GPU 资源

```yaml
apiVersion: resource.k8s.io/v1
kind: ResourceClaimTemplate
metadata:
  name: single-gpu-template
  namespace: default
spec:
  spec:
    devices:
      requests:
      - name: gpu
        exactly:
          deviceClassName: gpu.nvidia.com
          allocationMode: ExactCount # exactly,精确匹配某类设备,数量固定；firstAvailable:提供多个候选请求,按顺序选第一个能满足的(用于"要么用 A 型号,不行就退而求其次用 B 型号"这种场景)
          count: 1 # 如果一个 Pod 想要多张卡,把 count 改成想要的数量(默认是 1)
          selectors:           # 可选:按属性筛选设备。这里按型号精确匹配 A800。不需要筛选的话可以删掉整个 selectors 字段。
          - cel:
              expression: "device.attributes['gpu.nvidia.com'].productName == 'NVIDIA A800-SXM4-80GB'"
```

然后创建 Pod 指定使用这个 resourceClaimTemplate，通过 resourceClaimTemplateName 指定名称进行关联。

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: single-gpu
spec:
  selector:
    matchLabels:
      app: single-gpu
  template:
    metadata:
      labels:
        app: single-gpu
    spec:
      containers:
      - name: single-gpu
        image: swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/nvidia/cuda:13.0.0-devel-ubuntu22.04
        command:
          - sleep
        args:
          - infinity
        resources:
          limits:
            cpu: "8"
            memory: "32Gi"
          claims:
          - name: gpu   # 与下面 resourceClaims 里的 name 对应
      resourceClaims:
      - name: gpu       # 容器里引用的名字
        resourceClaimTemplateName: single-gpu-template # 刚刚定义的ResourceClaimTemplate
```

# HAMi 部署并启用DRA
HAMi 最近的 2.9 版本已经正式接入了 DRA，用户既可以使用原生 DRA 模式，也可以用 DevicePlugin 兼容模式无缝迁移。

## 模式区别
### 传统模式（Device Plugin）
```plain
Pod 提交 → HAMi mutating webhook（改 annotation）
        → hami-scheduler（k8s scheduler extender，做 filter/score/bind）
        → hami-device-plugin（kubelet 插件，Allocate() 实际分配）
        → nvidia-container-runtime hook 注入设备
```

这是 HAMi 自己实现的一套旁路机制：借助 Kubernetes 的 Extender API（老式扩展点）接管调度决策，资源以 `nvidia.com/gpu`、`nvidia.com/gpumem` 这类扩展资源（Extended Resource）的形式上报给 kubelet。

### DRA 模式
```plain
Pod 提交 → hami-dra-webhook（自动把资源请求转成 ResourceClaim）
        → kube-scheduler 内置的 DRA 调度插件（原生调度决策，不再是 extender）
        → hami-dra-driver-kubelet-plugin（DRA Driver，通过 CDI 注入设备）
```

这是站在 Kubernetes 官方 DRA 标准之上做的实现，调度决策完全交给 kube-scheduler 原生的 DRA 插件处理，HAMi 只负责"翻译"用户请求和"实现"设备驱动这两端，不再需要自己维护一个 scheduler extender。

## 两种模式对比
| 维度 | 传统模式 | DRA 模式 |
| --- | --- | --- |
| K8s 版本要求 | 无特殊限制，兼容性好 | ≥1.34，且需开启 `DRAConsumableCapacity`feature gate |
| 调度机制 | Scheduler Extender（HAMi 自研，webhook + extender API） | Kubernetes 原生 DRA 调度框架（社区标准） |
| 资源声明方式 | Extended Resource（`nvidia.com/gpu: 1`），kubelet capacity/allocatable 汇报 | `ResourceClaim`/ `ResourceClaimTemplate`（结构化 API 对象），或兼容层自动转换 |
| 设备注入 | nvidia-container-runtime hook（legacy 机制） | CDI（Container Device Interface，containerd/CRI-O 原生支持） |
| GPU Operator 配置 | `cdi.enabled=false`，让 operator 把 `nvidia`设为默认 runtime | `cdi.enabled=true`，必须开 CDI |
| 节点标记 | 需要手动 `kubectl label node gpu=on` | 不需要，节点 GPU 自动发现并发布为 `ResourceSlice` |
| 组件 | `hami-scheduler`+ `hami-device-plugin` | `hami-dra-webhook`+ `hami-dra-driver-kubelet-plugin`+ `hami-dra-monitor` |
| Helm Chart | `hami-charts/hami` | `hami-dra/hami-dra`（独立仓库） |
| 依赖 | 无额外依赖 | 依赖 cert-manager（webhook TLS 证书） |
| 成熟度 | 生产验证多年，功能最全（MIG、拓扑感知、多种调度策略都成熟） | v2.9.0 才 GA（2026年5月），相对新，设备支持目前只有 NVIDIA GPU |
| Pod YAML 写法 | `resources.limits.nvidia.com/gpu`等 | 两种都支持：`resources.claims`（原生）或兼容层沿用 `resources.limits`写法 |

## 使用
创建 ResourceClaimTemplate 申请一个 GPU 资源

```yaml
apiVersion: resource.k8s.io/v1
kind: ResourceClaimTemplate
metadata:
  name: hami-gpu-template
  namespace: default
spec:
  spec:
    devices:
      requests:
      - name: gpu
        exactly:
          deviceClassName: hami-core-gpu.project-hami.io
          allocationMode: ExactCount
          count: 1
          capacity:
            requests:
              cores: 50 # 分配 50% 算力
              memory: "10Gi" # 分配 10Gi 显存
```

然后创建 Pod 指定使用这个 resourceClaimTemplate，通过 resourceClaimTemplateName 指定名称进行关联。

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: single-gpu
spec:
  selector:
    matchLabels:
      app: single-gpu
  template:
    metadata:
      labels:
        app: single-gpu
    spec:
      containers:
      - name: single-gpu
        image: swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/nvidia/cuda:13.0.0-devel-ubuntu22.04
        command:
          - sleep
        args:
          - infinity
        resources:
          limits:
            cpu: "8"
            memory: "32Gi"
          claims:
          - name: gpu   # 与下面 resourceClaims 里的 name 对应
      resourceClaims:
      - name: gpu       # 容器里引用的名字
        resourceClaimTemplateName: hami-gpu-template # 刚刚定义的ResourceClaimTemplate
```
