# Linux 日志与故障定位

## 日志容量与保留

按峰值日志速率、压缩比、保留天数、故障窗口和恢复并发计算磁盘与队列容量。轮转必须验证服务能重新打开文件；容器 stdout、文件日志和审计日志应分别设置配额，避免单一服务填满根分区。

故障定位报告至少包含首次异常时间、受影响请求样本、request ID、最近变更、资源指标、止血动作和验证结果。对采集链路做断链演练，确认缓冲、补传、丢弃优先级和告警符合预期。

## 日志分层

内核日志说明资源和驱动，systemd journal 说明服务生命周期，应用日志说明业务语义，访问日志说明请求路径。先建立统一时间线和 request ID，再按层关联，不要只搜索“error”。

```bash
journalctl -b -1 -p err..alert; journalctl -u nginx --since '30 min ago' -o short-iso; dmesg -T | egrep -i 'oom|error|reset|corrupt'
```

## 故障定位流程

确认影响范围（单请求、单节点、单可用区或全局），对齐代码/配置/证书/依赖/容量变更，再从状态码、上游耗时、资源/锁和外部依赖逐层收敛。先止血再取证：限流、摘除节点或只读降级，但保留原始日志和时间点。

日志统一使用带时区的 ISO-8601 时间，字段化记录主机、服务、版本、request ID、延迟和结果。对密码、Token、Cookie、身份证号和支付数据做源头脱敏；轮转同时设置大小、时间、压缩、保留和磁盘水位。

日志缺失可能是时间不同步、级别过高、磁盘满、采集队列阻塞或程序写入错误。清理日志前先保存取证副本并记录 hash；涉及安全事件时使用只读副本和访问审计。
