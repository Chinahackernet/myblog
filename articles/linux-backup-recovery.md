# Linux 备份与恢复策略

## RPO/RTO

RPO 是可接受的数据丢失窗口，RTO 是恢复到可服务状态的时间。全量、增量、快照和复制解决不同问题；快照不能替代异地、离线和不可变备份。

配置和 IaC 进入版本库；数据库使用一致性备份并保留 binlog/WAL；文件和对象按增量策略复制；密钥使用独立密钥管理系统。备份跨主机、区域和凭据边界，备份账号不能删除所有副本。

```bash
tar --xattrs --acls -czf etc-backup.tgz /etc; sha256sum etc-backup.tgz > etc-backup.tgz.sha256
```

每次备份成功只证明任务完成，不证明可恢复。定期在隔离环境恢复系统配置、数据库、证书和应用，校验 hash、数据库一致性、权限、TTL、业务对账和实际 RTO。恢复流程要有断点、幂等和清理动作。

主机损坏优先重建基础设施；误删按时间点恢复；勒索或凭据泄漏时使用不可变副本和新凭据；区域故障按 DNS、网络、身份、存储、数据库、应用顺序恢复。恢复后观察双写、重复消费和旧客户端连接。

## 恢复优先级

先恢复身份、网络、密钥和监控，再恢复存储、数据库、消息队列和无状态应用。每个依赖定义“可用”判定，例如数据库不仅要能接受连接，还要完成关键查询、复制和权限校验。恢复期间使用临时 DNS/VIP 与隔离凭据，避免旧环境重新写入。

备份任务监控应覆盖开始/结束时间、字节数、校验结果、最后成功年龄、目标剩余空间和复制延迟。连续失败时冻结自动清理，保留最近可恢复副本并升级；恢复演练结束后销毁临时数据和临时授权。
