# Web 应用安全评估指南：生产环境只读与非入侵式实践

> 本文基于一次真实的安全评估需求确认过程整理而成。当目标环境仅限生产、且要求只读/非入侵式检查时，如何在"不触碰、不改变"的前提下最大化发现安全风险？这是一份可直接落地的操作指南。

## 背景

Web 应用安全评估通常分为**白盒**（源码审计）、**灰盒**（结合源码与运行态）、**黑盒**（仅从外部探测）三种模式。当面对以下约束时——

- 目标环境为**生产环境**
- 仅允许**只读/非入侵式**检查
- 无法获取源码

——评估策略需要做大幅调整：从主动利用转向被动侦察，从代码审计转向运行态指纹识别，从 SAST 转向版本/CVE 对照。

## 评估范围与约束

### 约束定义

| 约束项 | 说明 |
|--------|------|
| 环境 | 仅生产环境 |
| 模式 | 只读 / 非入侵式 |
| 禁止行为 | 不注入载荷（SQLi/XSS）、不尝试认证绕过、不爆破、不 fuzz、不提交会改变数据的请求 |
| 允许行为 | 被动侦察、只读配置检查、公开信息收集、版本/CVE 对照 |

### 评估深度

- 快速自查（OWASP Top 10 覆盖 + 清单）
- **深入评估**（运行态指纹 + 依赖/SCA 版本对照 + 配置审查）
- 威胁建模（STRIDE + 数据流 + 信任边界）

> **白盒降级说明**：生产黑盒拿不到源码时，代码审计部分降级为基于运行态的指纹识别（从响应头、Cookie、静态资产文件推断技术栈与版本），依赖审计改为公开 CVE/版本对照。

## 六大检查域

### 1. 被动侦察 — 暴露面编目

在不向目标发送异常请求的前提下，收集尽可能多的公开信息。

**检查项：**

- [ ] 域名与子域名暴露面（DNS 记录、证书透明度日志）
- [ ] WHOIS 信息（注册商、注册时间、联系人）
- [ ] 公开资产与服务端口（Shodan、Censys 等被动数据源）
- [ ] 历史泄露线索（GitHub、Pastebin、Wayback Machine）
- [ ] 技术栈指纹（从响应头、Cookie 名称、静态资源路径推断）

**产出：** 暴露面资产清单 + 技术栈推断报告

### 2. 传输层安全 — TLS 配置审查

**检查项：**

- [ ] TLS 版本（是否仍支持 TLS 1.0/1.1，目标应为 TLS 1.2+，推荐 1.3）
- [ ] 密码套件强度（禁用 RC4、3DES、CBC 模式，优先 GCM/ChaCha20）
- [ ] 证书链完整性（中间证书是否正确下发）
- [ ] 证书有效期与到期告警
- [ ] HSTS 是否启用（`Strict-Transport-Security` 响应头）
- [ ] HSTS preload 列表状态
- [ ] HTTP → HTTPS 自动跳转是否强制

**工具推荐：**

- SSL Labs（https://www.ssllabs.com/ssltest/）— 在线 TLS 深度检测
- `testssl.sh` — 本地命令行 TLS 扫描
- `curl -vI https://target` — 快速查看响应头

**严重性参考：**

| 问题 | 严重性 | 理由 |
|------|--------|------|
| 支持 TLS 1.0 | 中危 | 已知弱协议，PCI DSS 明确禁止 |
| 无 HSTS | 中危 | 首次访问可被中间人降级 |
| RC4 密码套件 | 高危 | 已被证明不安全 |
| 证书过期 | 高危 | 用户看到安全警告，信任受损 |
| 自签名证书（生产） | 严重 | 无信任链，完全无法防御中间人 |

### 3. HTTP 安全响应头 — 纵深防御基线

安全响应头是浏览器端的最后一道防线。每一个缺失的头都是一次攻击机会。

**检查清单：**

| 响应头 | 作用 | 推荐值 |
|--------|------|--------|
| `Content-Security-Policy` | 防止 XSS、数据注入、代码执行 | `default-src 'self'; script-src 'self' 'nonce-{random}'; ...` |
| `Strict-Transport-Security` | 强制 HTTPS | `max-age=63072000; includeSubDomains; preload` |
| `X-Content-Type-Options` | 防止 MIME 类型嗅探 | `nosniff` |
| `X-Frame-Options` | 防止点击劫持 | `DENY` 或 `SAMEORIGIN`（CSP `frame-ancestors` 可替代） |
| `Referrer-Policy` | 控制 Referer 泄露 | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | 限制浏览器 API 权限 | 按需禁用 `camera`、`microphone`、`geolocation` 等 |
| `Cross-Origin-Opener-Policy` | 隔离顶级浏览上下文 | `same-origin` |
| `Cross-Origin-Resource-Policy` | 限制跨域资源加载 | `same-site` 或 `same-origin` |

**信息泄露检查：**

- [ ] `Server` 头是否暴露了精确版本号（如 `nginx/1.21.3`）
- [ ] `X-Powered-By` 头是否暴露了框架信息（如 `Express`、`PHP/7.4.3`）
- [ ] 自定义错误页是否泄露堆栈跟踪、文件路径、SQL 错误
- [ ] `Set-Cookie` 中是否包含会话 ID 命名约定暴露的框架线索

**严重性参考：**

| 问题 | 严重性 | 理由 |
|------|--------|------|
| 缺失 CSP | 高危 | 存储型 XSS 可直接执行任意脚本 |
| `Server` 头暴露精确版本 | 低危 | 辅助攻击者定位已知 CVE |
| 错误页泄露堆栈跟踪 | 中危 | 泄露内部路径、技术栈、库版本 |
| 无 `X-Content-Type-Options` | 低危 | 旧浏览器 MIME 嗅探攻击 |

### 4. CORS 策略 — 跨域信任边界

CORS 配置错误是现代 Web 应用中最常见的高危漏洞之一。

**检查项：**

- [ ] `Access-Control-Allow-Origin` 是否为 `*` 且搭配 `Allow-Credentials: true`（**严重漏洞**）
- [ ] 是否反射任意 Origin 且搭配 `Allow-Credentials: true`（**严重漏洞**）
- [ ] 白名单是否使用精确匹配而非子串匹配（如 `target.com` 匹配了 `eviltarget.com`）
- [ ] 预检请求（OPTIONS）是否正确处理
- [ ] `Access-Control-Allow-Headers` 是否过宽（如允许 `Authorization` 对所有来源）
- [ ] `Access-Control-Allow-Methods` 是否包含不必要的状态变更方法（PUT/DELETE）

**严重性参考：**

| 问题 | 严重性 | 理由 |
|------|--------|------|
| `*` + `credentials: true` | 严重 | 任意网站可代替用户发起已认证请求 |
| 反射 Origin + credentials | 严重 | 同上，且更隐蔽 |
| 子串匹配白名单 | 高危 | 钓鱼域名可绕过白名单 |

### 5. 认证与授权 — 信任边界验证

在只读模式下，不尝试认证绕过，而是从**可观察的运行态行为**推断安全质量。

**检查项：**

- [ ] 登录页是否存在（路径枚举：`/login`、`/admin`、`/signin`、`/auth`）
- [ ] 登录请求是否通过 HTTPS 传输（明文 HTTP 登录 = 严重）
- [ ] Cookie 安全标志：
  - `HttpOnly` — 防止 JavaScript 读取
  - `Secure` — 仅 HTTPS 传输
  - `SameSite=Strict|Lax` — 防止 CSRF
- [ ] 会话 Token 是否在 URL 中传递（`?session=xxx` — 严重，会通过 Referer 泄露）
- [ ] 登出后会话是否立即失效（无法在只读模式下验证，标记为待验证项）
- [ ] JWT 使用情况（从 Cookie/LocalStorage/请求头中观察）：
  - 算法是否为 `none`（严重）
  - 是否使用弱密钥（HS256 + 短密钥）
  - 是否暴露在 URL 或 LocalStorage 中（XSS 可窃取）
- [ ] 密码策略是否可从注册页/前端代码推断
- [ ] 是否存在多因素认证（MFA）入口

**严重性参考：**

| 问题 | 严重性 | 理由 |
|------|--------|------|
| 明文 HTTP 登录 | 严重 | 凭据可被中间人截获 |
| 会话 ID 在 URL 中 | 严重 | 通过 Referer/日志/历史记录泄露 |
| JWT `alg: none` | 严重 | 认证完全可绕过 |
| Cookie 无 `HttpOnly` | 高危 | XSS 可直接窃取会话 |
| Cookie 无 `SameSite` | 中危 | CSRF 攻击面扩大 |
| 无 MFA | 中危 | 凭据泄露后无第二道防线 |

### 6. API 暴露面 — 端点与数据过度暴露

**检查项：**

- [ ] 已知 API 路径探测（`/api`、`/api/v1`、`/api/v2`、`/graphql`、`/swagger`、`/openapi.json`）
- [ ] OpenAPI/Swagger 文档是否公开暴露（生产环境应禁用）
- [ ] GraphQL 内省是否启用（生产环境应关闭）
- [ ] API 响应是否过度暴露内部字段（如 `password_hash`、`internal_id`、`debug`）
- [ ] API 是否缺少速率限制（从响应头 `X-RateLimit-*` 或 `Retry-After` 判断）
- [ ] 是否存在未认证可访问的敏感端点
- [ ] WebSocket 端点（`wss://`）是否在升级时验证 Origin 和认证

**严重性参考：**

| 问题 | 严重性 | 理由 |
|------|--------|------|
| Swagger/OpenAPI 生产暴露 | 中危 | 攻击者免费获得完整 API 地图 |
| GraphQL 内省启用 | 中危 | 暴露完整 Schema，可构造精确攻击 |
| API 响应包含 `password_hash` | 严重 | 敏感数据过度暴露 |
| 无速率限制 | 中危 | 暴力破解、爬取无阻拦 |

## 严重性评级标准

采用 CVSS 3.1 思路，结合可利用性和业务影响：

| 等级 | 定义 | 典型示例 |
|------|------|----------|
| **严重（Critical）** | 远程未认证可利用，影响机密性/完整性/可用性 | 明文 HTTP 登录、CORS `*`+credentials、JWT `alg:none` |
| **高危（High）** | 需要一定条件但可导致数据泄露或认证绕过 | 缺失 CSP（有存储型 XSS 风险）、Cookie 无 HttpOnly |
| **中危（Medium）** | 需要特定条件或影响有限 | 无 HSTS、无速率限制、Swagger 生产暴露 |
| **低危（Low）** | 信息泄露或纵深防御改进 | Server 头暴露版本、无 X-Content-Type-Options |
| **信息（Informational）** | 最佳实践偏差 | 无 Permissions-Policy、COOP/CORP 未设置 |

## 报告模板

每项发现应包含以下结构：

```markdown
### [严重性] 发现标题

**风险等级：** 严重 / 高 / 中 / 低 / 信息
**OWASP 分类：** A01:2021-Broken Access Control
**CWE 编号：** CWE-79

**描述：**
简述漏洞是什么、在哪里被发现。

**利用路径：**
1. 攻击者访问 /api/users?id=1
2. 修改 id 参数为 2（IDOR）
3. 获取其他用户的个人资料

**爆炸半径：**
影响所有 50,000 名注册用户的个人数据。

**修复方案：**
\```http
# 修复前（缺失授权检查）
GET /api/users/1/documents HTTP/1.1

# 修复后（添加对象级授权）
# 服务器端验证：请求者 ID == 资源所有者 ID
\```

**参考：**
- OWASP: https://owasp.org/...
- CWE: https://cwe.mitre.org/...
```

## 工具推荐

### 只读/非入侵式工具

| 工具 | 用途 | 入侵性 |
|------|------|--------|
| `curl` / `httpie` | 手动请求与响应头检查 | 极低 |
| SSL Labs | TLS 配置深度检测 | 无 |
| `testssl.sh` | 本地 TLS 扫描 | 极低 |
| Mozilla Observatory | 安全响应头评分 | 无 |
| SecurityHeaders.com | 响应头快速检查 | 无 |
| `nmap`（默认脚本） | 端口与服务识别 | 低（注意：某些脚本可能被 IDS 标记） |
| Wayback Machine | 历史快照与泄露线索 | 无 |
| `wappalyzer` | 技术栈指纹识别 | 无 |
| NVD / OSV.dev | CVE 查询 | 无 |

> ⚠️ **注意**：即使是"只读"工具，高频请求也可能触发 WAF/IDS 告警。控制请求速率，单次请求间隔 ≥ 2 秒。

## 关键原则

1. **不改变状态** — 任何请求都不应导致服务器数据变化。GET 可以，POST/PUT/DELETE 禁止。
2. **最小请求量** — 每个请求都有目的，不做无意义的扫描。
3. **控制速率** — 避免触发速率限制或 IDS 告警，建议间隔 ≥ 2 秒。
4. **不尝试利用** — 发现潜在漏洞时，记录并标记，不发送利用载荷。
5. **授权优先** — 即使是只读检查，也必须拥有合法授权。

## 结语

生产环境的安全评估不必"入侵"才能发现风险。一个配置错误的 CORS 头、一个缺失的 HSTS、一个暴露的 Swagger 文档——这些都是在只读模式下可以发现的**真实高危问题**。

安全评估的价值不在于"我能攻破什么"，而在于"我能在攻击者之前发现什么"。非入侵式评估虽然深度有限，但它**安全、可重复、不会中断业务**，是持续安全监控的第一选择。
